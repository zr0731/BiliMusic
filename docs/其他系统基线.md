# 其他系统基线

本 fork 只面向 Windows 10/11。下面这些内容来自 Withnoidea/BiliMusic，删除前与提交 `73e6b12792a5fafe449345187926dedfeddf5023`（2026-10-10，update docs）一致。本 fork 没有改过这些文件。

以后如果要做鸿蒙、macOS 或 Linux，不要凭记忆重写。重新克隆作者仓库，再按这份清单把对应文件拷回来：

```text
git clone https://github.com/Withnoidea/BiliMusic.git
cd BiliMusic
git checkout 73e6b12792a5fafe449345187926dedfeddf5023
```

作者仓库当时能覆盖的系统：

- Windows：Electron 安装包，NSIS。这是本 fork 保留的目标。
- macOS：electron-builder 打 DMG 和 ZIP。仓库里没有单独的 macOS 工程目录。
- Linux：electron-builder 打 AppImage 和 deb。仓库里没有单独的 Linux 工程目录。GitHub Actions 还在 Linux job 上打过一次与平台无关的 OTA 渲染包。
- 鸿蒙 PC：`platform/HarmonyOS/` 是一套 DevEco / Hvigor 工程，平台判断用 `process.platform === 'openharmony'`。

界面类名 `apple-search`、字体栈里的 `-apple-system`、Apple Music 风格组件，都是视觉样式，不是 macOS 版本，所以没有删。`playlistImportApi.ts` 里的 `platform=yqq` 是 QQ 音乐接口参数，也不是操作系统。`node_modules` 里各平台的可选二进制是依赖安装产物，不是作者写的工程文件，没有删。

## 已从本 fork 删除的独立文件

共 204 个已跟踪路径：`platform/HarmonyOS/` 下 202 个，加上两个脚本。

- `scripts/prepare-harmony.mjs`：把构建结果同步进鸿蒙工程的资源目录。
- `scripts/build-harmony.mjs`：调用 Hvigor 打 HAP。找不到工具时提示用 DevEco Studio 打开 `platform/HarmonyOS`。

`platform/HarmonyOS/` 的组成：

- `AppScope/`：应用名、图标和配置。
- `electron/`：鸿蒙入口 Ability、窗口页面、托盘图标和测试。
- `web_engine/`：Electron 在鸿蒙上的适配层。`adapter/` 是系统能力，`jsbindings/` 把这些能力接到 JavaScript，`components/` 是网页窗口。
- `docs/`：鸿蒙上加载 Electron addon 的说明和示例压缩包。
- 根上的 `build-profile.json5`、`hvigorfile.ts`、`oh-package.json5`、`hvigor/hvigor-config.json5`：Hvigor 工程文件。

## 从共用文件里摘掉的配置

这些不是单独文件。Windows 构建还要用同一份 `package.json` 和同一份工作流，所以只删了其他系统的那一段。原文如下，恢复时放回原处。

`package.json` 的脚本：

```json
"harmony:prepare": "npm run build && node scripts/prepare-harmony.mjs",
"harmony:build": "npm run harmony:prepare && node scripts/build-harmony.mjs"
```

`package.json` 的 `build`：

```json
"mac": {
  "target": ["dmg", "zip"],
  "icon": "electron/icon.png",
  "category": "public.app-category.music",
  "artifactName": "${productName}-${version}-${arch}.${ext}"
},
"dmg": {
  "title": "${productName} ${version}"
},
"linux": {
  "target": ["AppImage", "deb"],
  "icon": "electron/icon.png",
  "category": "AudioVideo",
  "maintainer": "Hanversion <hanversion@gmail.com>",
  "synopsis": "基于 Bilibili 的桌面音乐播放器",
  "artifactName": "${productName}-${version}-${arch}.${ext}"
}
```

`.github/workflows/build.yml` 原来的矩阵：

```yaml
- os: windows-latest
  args: --win --x64 --ia32 --arm64
- os: macos-latest
  args: --mac --x64 --arm64
- os: ubuntu-latest
  args: --linux --x64 --arm64
```

Linux job 额外执行 `node scripts/build-ota.mjs`。这个脚本打的是渲染层热补丁，本身不依赖 Linux。本 fork 把这一步留在 Windows job 上。上传路径里原来还有 `release/*.dmg`、`release/*.zip`、`release/*.AppImage`、`release/*.deb`。发布 job 仍使用 `ubuntu-latest`，它只上传已经打好的 Windows 产物，不打包 Linux。

## 留在共用源码里的平台分支

下面这些文件 Windows 还在用，没有删除。里面的 `openharmony` 或 `darwin` 判断在 Windows 上不会走进去。恢复其他系统时，除了拷回上面的工程，还要对上这些分支。

- `electron/main.ts`：`isHarmonyOS`。鸿蒙不改 `userData` 目录；托盘用 `tray.png`，并且不创建托盘弹出窗口；窗口不用 `titleBarStyle: 'hidden'`；`window:set-button-visibility` 只在鸿蒙调用原生按钮显隐；启动时先建托盘再建窗口。`darwin` 只处理 Dock 显示、隐藏，以及关闭全部窗口后不退出。
- `electron/updater.ts`：macOS 和鸿蒙不走 electron-updater 自动下载整包。
- `electron/preload.cjs`：把 `process.platform` 暴露给渲染层。
- `src/components/layout/TitleBar.tsx`：平台是 `openharmony` 时不画自绘的最小化、最大化和关闭按钮。
- `src/components/NowPlaying.tsx`：全屏播放页展开时，在鸿蒙上隐藏原生窗口按钮。
- `src/utils/persistentStorage.ts`：只在 `openharmony` 上镜像到主进程持久存储。Windows 仍走 `localStorage`。
- `electron/updaterBus.ts`：注释里写了鸿蒙日志进 hilog。代码本身是共用的。

文档里原来也写了其他系统，文件本身保留，只改了会让人以为本 fork 仍支持那些系统的句子：

- `README.md`：运行环境从「Windows 10/11 x64（macOS / Linux 亦支持前端开发）」改为只写 Windows。
- `README.en.md`：英文说明仍保留作者原文，开头加了本 fork 已删除这些目标的提示。鸿蒙章节描述的是作者仓库，不是当前目录。
- `docs/RELEASING.md`：发布流程改为只打 Windows 包。
- `项目入门资料/项目概览.md`：去掉「仓库里另有一份鸿蒙 PC 移植」。
- `CLAUDE.md`：作者原文未改。改写后的 Cursor 稿在仓库根目录 `BiliMusic项目规则.mdc`，还没有放进 `.cursor/rules`。
